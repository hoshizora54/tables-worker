## Стратегия бенчмаркинга для агентной системы анализа Excel/CSV

### Цель
Оценивать качество и надежность агентной системы с инструментами (Tool Use) для анализа табличных данных (CSV/XLSX) по двум направлениям:
- точность и полнота ответов/преобразований данных;
- устойчивость и пригодность к продакшену (стабильность, воспроизводимость, покрытие типовых сценариев).

### Обзор релевантных бенчмарков и датасетов
Хотя специализированных бенчмарков для «агентного анализа Excel/CSV» мало, существуют близкие области:
- Text-to-SQL: Spider, WikiSQL — подходят для оценки генерации SQL и корректности выполнения запросов на реляционных схемах.
- Табличные QA/анализ: TabFact (верификация фактов по таблицам), TableQA/TableQA-like, WikiTableQuestions — оценка понимания табличных данных на естественном языке.
- Визуализация из НЛ (NL2VIS): ChartBench/ChartQA — оценка преобразования НЛ-запросов в спецификации графиков.
- Прикладные датасеты на Kaggle (продажи/маркетинг/финансы/веб-аналитика) — богаты задачами для бизнес- и маркетинг-аналитики, могут быть конвертированы в бенчмарк с вопросами/целями.

Вывод: прямого «agent + tools for CSV/XLSX» бенчмарка нет; берем компоненты из Text-to-SQL, Табличного QA и NL2VIS и конструируем над ними интеграционный сценарный бенчмарк.

### Что именно измеряем
- Точность ответа/результата: совпадение результата выполнения (execution match) с эталоном; допускаем числовую погрешность (epsilon) для вещественных величин.
- Корректность преобразований: для write-операций проверяем итоговое состояние таблицы против ожидаемого снепшота (полн. равенство схемы и данных, за вычетом упорядочивания строк).
- Графики: правильный выбор данных и тип графика. Метрики:
  - точность данных (совпадение агрегированных рядов);
  - структурная близость спецификации (тип, каналы x/y/hue, агрегирование, биннинг) — метрика частичного совпадения полей.
- Статистические задачи (t-тест, ANOVA): корректность p-value/статистики в пределах числовой погрешности.
- Надежность: стабильность при повторных запусках (детерминизм при фиксированных seed, время/затраты, процент ошибок).

### Метрики и критерии
- Для SELECT/NLQuery: Execution Accuracy = доля кейсов, где результат совпадает с эталоном (с учетом сортировки/переупорядочивания и epsilon для float).
- Для write-операций: Snapshot Accuracy = доля кейсов, где финальное состояние таблицы эквивалентно эталону (схема и данные).
- Для графиков: Data Accuracy (MAE/R² по рядам), Spec Match (Jaccard по наборам обязательных полей), Chart-Type Accuracy.
- Для статтестов: Δp ≤ eps и |Δstat| ≤ eps_stat.
- Производительность: среднее/95-й перцентиль времени и стоимости, % таймаутов.

### Набор задач и покрытие
1) Бизнес-аналитика:
   - агрегирования (SUM/AVG/MIN/MAX/COUNT) с группировкой по нескольким полям;
   - фильтрации (диапазоны дат, категориальные фильтры, сложные условия);
   - сводные таблицы (pivot);
   - расчет скользящих средних;
   - объединения таблиц (join/union сценарио);
   - экспорт/версионирование (проверка восстановления).

2) Маркетинг-аналитика:
   - t-тест (две группы: межтаблично/внутритаблично);
   - ANOVA (несколько групп);
   - расчет размера выборки (по уровню значимости, мощности, ожидаемому эффекту).

3) Визуализации:
   - bar/line/hist/scatter (+опционально box/violin);
   - проверка правильности выбора осей, агрегирования, биннинга.

Покрытие: сбалансированный пул из 150–300 кейсов, из них ~60% чтение/агрегирование, ~20% визуализация, ~20% статанализ/инструменты. Данные — 5–10 разнообразных CSV/XLSX из публичных источников (продажи, веб-аналитика, маркетинг, финансы, логистика).

### Как построить бенчмарк из открытых датасетов
1) Подбор датасетов (Kaggle/открытые порталы) с ясной схемой/семантикой.
2) Формирование набора заданий на естественном языке + эталонных ответов:
   - для SELECT — эталон SQL и/или эталонный результат (parquet/json);
   - для графиков — эталонная спецификация (JSON) и эталонные ряды;
   - для write — эталонный снепшот таблицы после операции;
   - для статтестов — эталон статистики/p-value.
3) Нормализация формата бенчмарка (JSONL): {dataset, files[], task_type, instruction, table_hint?, expected: {...}}.
4) Проверка валидности: скрипт верификации эталонов (пересчет ожидаемого результата напрямую из исходных CSV/XLSX).

### Инфраструктура оценки
- «Оффлайн-харнесс» (скрипт) для пакетного прогона кейсов: загрузка исходных файлов → выполнение задачи через API → сравнение с эталоном → лог результатов и метрик.
- Детерминизм: фиксируем seeds/параметры; ограничение на время/стоимость; ретраи только для сетевых ошибок.
- Отчёт: сводная таблица метрик по датасетам/типам задач; хистограммы ошибок; выборка проваленных кейсов.

### Пороговые значения и таргеты
- Execution Accuracy (SELECT): ≥ 0.8 на базовых кейсах, ≥ 0.6 на сложных схемах.
- Snapshot/Write Accuracy: ≥ 0.95 на единичных операциях, ≥ 0.85 на пайплайнах из 2–3 операций.
- Chart-Type Accuracy: ≥ 0.9; Data Accuracy (MAE) — в пределах допусков домена.
- Статтесты: Δp ≤ 1e-6, |Δstat| ≤ 1e-6.
- Надежность: таймауты ≤ 2%, ошибки ≤ 1%.

### Итоги
Используем комбинацию существующих бенчмарков (Spider/WikiSQL, NL2VIS-подходы) и практических CSV/XLSX с вопросами/эталонами. Поставляем единый формат кейсов и оффлайн-харнесс для воспроизводимой оценки точности, удобства и надежности агентной системы.
